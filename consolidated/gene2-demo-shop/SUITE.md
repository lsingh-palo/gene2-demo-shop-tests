## Review

Fresh-context reviewer verdicts on the active tests: accepted 24, accepted-with-note 26.
- TC033 `test_double_submit_records_one_order`: bug reproduction - fails until the app is fixed
- TC032 `test_postcode_is_required`: bug reproduction - fails until the app is fixed
- TC030 `test_tax_is_eight_percent_of_subtotal`: Only subtotal $42.50 (exact $3.40), so REQ-TAX rounding is never exercised. Add a rounding case, e.g. $9.99 -> $0.80.
- TC003 `test_locked_account_is_refused`: Asserts the REQ-LOCK message only. Add an assertion that login did not succeed (URL stays on login page).
- TC011 `test_name_sort_a_to_z`: name-asc is the default sort, so the grid is already A to Z on first render and the assertion passes on its first poll. It proves the comparator, not the act of choosing A to Z. Select another sort first to test that.
- TC036 `test_orders_of_75_or_less_pay_flat_shipping`: Matches REQ-SHIP at $42.50 and $74.00. The $75.00-exact 'or less' case is not reachable with this catalogue, so the boundary is never tested.
- TC035 `test_orders_over_75_ship_free`: Matches REQ-SHIP at $162.50 and $76.49. No cart totals exactly $75.00, so a '>= 75' threshold, or any threshold between $74.00 and $76.49, would still pass. The catalogue causes this limit.
- TC005 `test_locked_account_cannot_reach_catalog`: The catalog-redirect check closes the first-poll race on the URL check. The error-visible barrier accepts any error; asserting the REQ-LOCK text would stop a wrong locked credential from passing silently.
- TC023 `test_badge_counts_quantities`: A single cart line cannot tell 'sum of quantities' from 'max/last line quantity'. Add a second line (p2 x3 + p5 x2 = 5).
- TC006 `test_customer_cannot_use_admin_page`: 'No admin controls' is checked only through the stock inputs. The promo switches are in the customer DOM (hidden). Assert admin-panel hidden.
- TC100 `test_order_history_newest_first`: SO-1001/SO-1002 are observed literals (REQ-ORDER-02 gives no format). The totals tie the test to tax, so on v2 it fails from the 10% tax although the order is correct. The date column is not asserted.
- TC083 `test_unknown_code_is_not_valid`: 'Changes nothing' is asserted only as discount $0.00, the starting value. Assert the total unchanged. Case-insensitivity from REQ-PROMO-01 is untested.
- TC082 `test_welcome5_needs_thirty_dollars`: $27.99 / $30.00 separates the $25 reading and pins >=, but any threshold from $28 to $30 passes. $29.97 (Espresso Cups x3) can be reached. The $0.00 discount after the refusal is the starting value.
- TC061 `test_review_text_length_limits`: Only the lower boundary 9/10 is pinned. The REQ-REVIEW-01 upper boundary 500/501 is untested (both builds handle it correctly today).
- TC060 `test_review_without_rating_is_rejected`: 'Not saved' is only review-item count 0, the starting state, so it passes on the first poll. Also assert pdp-rating still 'No reviews yet'.
- TC043 `test_every_product_appears_once_across_pages`: The deciding checks (18 cards, 18 distinct) are plain asserts that admission did not mutate. all_inner_texts does not retry. 'No Previous on page 1' from REQ-SEARCH-03 is not checked.
- TC040 `test_search_ignores_case`: The LAMP query starts from a list that already reads ['Desk Lamp'], so it passes on the first poll if rendering is async or the input is ignored. Clear the search and assert the reset between queries. 'Lamp' is not tested.
- TC092 `test_free_shipping_threshold_after_discounts`: The $76.49 Free half repeats existing TC035. The value is the SAVE10 half ($68.84 pays $6.50).
- TC091 `test_remote_shipping_is_always_fourteen`: FREESHIP is never shown to be accepted before switching to Remote, so the FREESHIP half passes even if the code did nothing. Assert shipping 'Free' under Metro first.
- TC071 `test_admin_zero_stock_blocks_adding`: Checks only the Featured list. REQ-STOCK-01 / SHOP-17 require every list and the product page. Add All products and product-page assertions.
- TC072 `test_low_stock_shows_only_n_left`: Only N=2 is tested, so the 1 to 3 range is not pinned. Scented Candle (p15, 3 left) gives the upper edge without admin. 4 needs admin.
- TC070 `test_out_of_stock_product_cannot_be_added`: The product-page button is only asserted disabled. REQ-STOCK-01 also requires it to read 'Out of stock' there.
- TC038 `test_place_order_shows_confirmation_and_empties_cart`: Round 2 (resubmitted after a round-1 rejection for a vacuous badge check on confirmation.html). Badge now asserted on cart.html (count 1, hidden); verified live that both the badge and cart-empty checks can fail. Weak spots: nothing asserts the cart was non-empty before the order (TC020 covers add-to-cart); REQ-CHK-02 promo clearing not covered; lines 26-29 not mutated by admission; REQ-PAY-01 only implicit.
- TC051 `test_product_page_from_catalog_shows_details`: Matches P-046 and REQ-PDP-01 (rating 4.5 out of 5 (2 reviews) verified live). Weak spots: the description check is only regex \S; the price is hardcoded $42.50 and not cross-checked against the catalog card; the review list required by REQ-PDP-01 is not asserted; the rating line was not mutation-tested (exact match, so not vacuous). Overlaps TC050 on the rating formula with a different data point; keep both.
- TC039 `test_empty_address_is_rejected`: Trailing orders-empty to_have_text is vacuous (element always in DOM, only hidden toggled); use to_be_visible() or order-row to_have_count(0). Docstring cites REQ-MSG-03, not in the plan's provenance for P-051.
- TC031 `test_full_name_length_is_enforced`: Boundary step tests only the rejecting side (1, 61); the accepting boundaries 2 and 60 are not asserted, so an off-by-one rejecting 2 or 60 would pass. Add them in a later plan.
- TC131 `test_postcode_must_be_six_digits`: bug reproduction - fails until the app is fixed
- TC008 `test_logout_clears_the_cart`: Round 2 (regenerated after a round-1 rejection for a vacuous cart-cleared oracle). TC038 pattern now: cart-empty visible, exact text, cart-item count 0, badge count 1 then hidden; would fail on a build whose logout keeps the cart (traced in the app source). Admission mutants only hit setup lines 28, 29, 31; the cart-cleared checks (lines 35-40) were not mutated.
